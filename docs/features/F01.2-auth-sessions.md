## Phạm vi và quyết định

| Chủ đề | Quyết định |
|---|---|
| Tài khoản được đăng nhập | `CUSTOMER/ACTIVE`, `VENUE_OPERATOR/ACTIVE`, `VENUE_OPERATOR/PENDING_ONBOARDING`. `PENDING_VERIFICATION`, `SUSPENDED` và `ADMIN` chưa có đường đăng nhập công khai trong F01.2; Admin thuộc F01.4. |
| Lỗi login | Sai contact/password, contact không tồn tại và trạng thái không được phép đều nhận cùng `401 INVALID_CREDENTIALS`; không tiết lộ account có tồn tại hay bị khóa. |
| Access token | JWT ký bằng secret cấu hình, mặc định hết hạn sau 10 phút (giới hạn 5–15 phút). Claim tối thiểu: `sub` (user ID), `sid` (session family ID), `accountType`, `status`, `iat`, `exp`, `iss`, `aud`, `jti`. Không chứa contact, password, refresh token hoặc permission/membership. |
| Refresh token | Secret ngẫu nhiên ít nhất 256 bit, truyền dạng base64url; DB chỉ lưu hash. Mặc định hết hạn sau 30 ngày. Mỗi lần refresh hợp lệ xoay token một lần trong transaction PostgreSQL. |
| Browser transport | API trả access và refresh token trong JSON. Hai portal chỉ giữ token trong React memory; không lưu localStorage, sessionStorage, URL hoặc log. Reload/đóng tab mất phiên ở client và cần đăng nhập lại. Không dùng cookie/credentials trong F01.2. |
| Thu hồi | Logout thu hồi toàn bộ family của phiên hiện tại. Dùng lại refresh token đã xoay sẽ thu hồi cả family, kể cả token con. Family khác không bị ảnh hưởng. |
| Trạng thái và quyền | Login/refresh đọc trạng thái user hiện tại. Protected endpoint phải kiểm tra lại user/session trong DB; claim `status` và `accountType` không đủ để cho phép thao tác. Operator còn phải qua membership, permission và resource scope theo `AGENTS.md`. `PENDING_ONBOARDING` chưa được vận hành sân/thanh toán. |
| Bảo vệ abuse | Rate limit login theo IP và hash contact; refresh theo IP/family khi nhận diện được; `429 RATE_LIMITED` có `Retry-After`. Audit `auth.login_succeeded`, `auth.login_failed`, `auth.refresh_rotated`, `auth.refresh_reuse_detected`, `auth.logout` với metadata đã redact. Không log password, token, Authorization header hoặc contact đầy đủ. |

Password reset, MFA, `remember me`, đăng nhập Admin và cookie session nằm ngoài F01.2. Client không được gửi `accountType`, `role`, `status` hoặc `userId` để tự quyết định danh tính. F02/F06 phải kiểm tra scope/trạng thái lúc thực hiện lệnh.

## Luồng và dữ liệu

```text
contact + password → normalize + PasswordHasher → đọc account type/status
                  → tạo session family + refresh token đầu tiên
                  → access token 10 phút + refresh token 30 ngày
refresh token hiện tại → transaction + lock row/family → đánh dấu đã dùng
                      → tạo refresh token con + access token mới
refresh token đã dùng → revoke cả family → token con bị từ chối
logout + bearer + refresh token cùng family → revoke family
```

Migration tăng dần F01.2 thêm bảng `refresh_tokens` (hoặc `auth_sessions` + `refresh_tokens` nếu tách family). Tối thiểu token có `id` UUIDv7, `user_id` FK, `family_id`, `token_hash` unique, `parent_token_id` nullable, `created_at`, `expires_at`, `consumed_at` nullable, `revoked_at` nullable và lý do thu hồi không chứa secret. Index hỗ trợ `(user_id, family_id)`, `token_hash` và expiration. Một family thuộc đúng một user; không cascade xóa user. Transaction/row lock hoặc conditional update ngăn hai request refresh đồng thời cùng tạo hậu duệ hợp lệ. Token đã dùng bị trình lại phải thu hồi cả family, không chỉ token cũ.

JWT signing key lấy từ cấu hình bí mật; `.env.example` chỉ chứa placeholder. Ứng dụng fail fast khi issuer, audience, signing key hoặc lifetime không hợp lệ; không có signing key mặc định production. Rotation phải commit trước khi response chứa token mới được trả. Refresh token rõ chỉ xuất hiện trong response HTTPS và memory client, không vào DB, audit hoặc log.

## API contract

Base path `/api/v1`; JSON camelCase. Thành công bọc `{ "data": ..., "traceId": "..." }`; lỗi `application/problem+json` có `status`, `code`, `traceId`. Body dùng allowlist và giới hạn kích thước; trường không nhận biết trả `400 UNSUPPORTED_FIELD`.

### Login

```http
POST /api/v1/auth/login
Content-Type: application/json

{"contactType":"email","contact":"customer@example.test","password":"Example-password-2026!"}
```

`contactType` là `email` hoặc `phone`; chuẩn hóa giống F01.1. Thành công `200 OK`:

```json
{
  "data": {
    "tokenType": "Bearer",
    "accessToken": "<jwt>",
    "expiresInSeconds": 600,
    "refreshToken": "<opaque-secret>",
    "refreshExpiresAt": "2026-10-24T00:00:00Z",
    "user": {"id":"<uuid>","accountType":"CUSTOMER","status":"ACTIVE"}
  },
  "traceId": "..."
}
```

Với owner mới xác minh, `accountType=VENUE_OPERATOR`, `status=PENDING_ONBOARDING`. Không đưa contact đầy đủ vào response. Login sai hoặc user bị suspend không tạo session.

### Refresh

```http
POST /api/v1/auth/refresh
Content-Type: application/json

{"refreshToken":"<opaque-secret>"}
```

Không yêu cầu access token còn hạn. Thành công `200 OK` trả cùng cấu trúc token/user như login với refresh token mới; token cũ bị consumed. Thiếu/sai/hết hạn/bị revoke trả `401 INVALID_REFRESH_TOKEN`. Token đã consumed xuất hiện lại trả cùng lỗi và revoke cả family trong transaction.

### Logout

```http
POST /api/v1/auth/logout
Authorization: Bearer <access-token>
Content-Type: application/json

{"refreshToken":"<opaque-secret>"}
```

Bearer phải hợp lệ/còn hạn; refresh token phải thuộc user và `sid` của bearer. Thành công `204 No Content`, thu hồi family hiện tại. Lặp lại logout bằng bearer đã bị thu hồi trả `401 UNAUTHORIZED` và không có side effect mới. Thiếu/sai bearer cũng trả `401 UNAUTHORIZED`; refresh token khác user/family trả `401 INVALID_REFRESH_TOKEN`. Sau logout, refresh và protected API với bearer family này bị từ chối. Client xóa token trong memory kể cả khi logout lỗi mạng.

### Lỗi

| HTTP/code | Ý nghĩa |
|---|---|
| `400 VALIDATION_FAILED` | JSON sai hoặc contact/password/token thiếu, sai định dạng/độ dài |
| `400 UNSUPPORTED_FIELD` | Có role/status/accountType hoặc field ngoài allowlist |
| `401 INVALID_CREDENTIALS` | Login thất bại, không phân biệt nguyên nhân |
| `401 INVALID_REFRESH_TOKEN` | Refresh/logout dùng refresh token không chấp nhận |
| `401 UNAUTHORIZED` | Protected API/logout thiếu hoặc sai bearer |
| `403 FORBIDDEN` | Bearer hợp lệ nhưng thiếu account type, status, membership, permission hoặc scope |
| `429 RATE_LIMITED` | Vượt limit, có `Retry-After` |
| `503 IDENTITY_UNAVAILABLE` | DB/signing service tạm không hoạt động, không tiết lộ cấu hình |

## UI contract

Customer portal thêm `/login` dùng email/phone và password; đăng nhập thành công hiển thị trạng thái phiên và logout. Partner portal có màn hình tương tự, chỉ chấp nhận `VENUE_OPERATOR`; `PENDING_ONBOARDING` thấy hướng dẫn chuẩn bị hồ sơ F02, không thấy thao tác vận hành đã duyệt. Cả hai portal hiển thị loading, lỗi generic và trạng thái hết hạn. Trong khi tab còn mở, access token hết hạn có thể refresh một lần bằng token hiện tại, thay cả hai token trong memory, và tránh hai refresh đồng thời trong cùng tab. Refresh thất bại thì xóa phiên và trở về login. Reload yêu cầu đăng nhập lại theo quyết định memory-only.

## Acceptance criteria

- AC01: Customer active và operator active/pending onboarding đăng nhập đúng; các trạng thái/loại khác và password sai nhận phản hồi generic, không tạo session.
- AC02: Access token có chữ ký, issuer/audience/expiry đúng, tối đa 15 phút, không chứa PII/secret; endpoint protected từ chối bearer sai/hết hạn.
- AC03: Refresh token ít nhất 256 bit, chỉ lưu hash; rotation một lần trong PostgreSQL transaction; token cũ không dùng được.
- AC04: Reuse token cũ thu hồi toàn family; race hai refresh hoặc refresh/logout không để lại hai phiên hợp lệ; family khác không bị ảnh hưởng.
- AC05: Logout thu hồi family của đúng bearer/user; protected API và refresh của family đó bị chặn; logout lặp không thêm side effect và bị từ chối do bearer đã thu hồi.
- AC06: User bị suspend sau login không thể refresh/dùng protected API; pending owner không có quyền vận hành resource trước F02/F06.
- AC07: Validation, rate limit, audit và redaction đạt contract; token không vào log, URL, database hoặc browser storage.
- AC08: Customer/partner UI dùng được login, refresh và logout; browser test thực chạy. Migration DB mới/lặp, API/database/concurrency/security test liên quan pass; reviewer không còn lỗi nghiêm trọng.
