## Mục tiêu, phạm vi và quyết định

F01.4 tạo **một** tài khoản quản trị nền tảng bằng thao tác vận hành nội bộ, cho phép Admin đăng nhập cổng riêng và thu hồi quyền truy cập khi cần. F01.1–F01.3 là nền: bảng `users`, password hasher, audit, JWT, refresh family và DTO/error conventions. PostgreSQL là nguồn dữ liệu chuẩn. F01.4 không tạo chức năng duyệt hồ sơ, quản lý business/venue, dispute, lời mời nhân viên hoặc quyền vận hành thuộc F02 trở đi.

| Chủ đề | Contract |
|---|---|
| Actor | Người vận hành có quyền chạy CLI nội bộ và truy cập cấu hình DB; Admin dùng `admin-web`. Khách và chủ sân không thể tự cấp Admin. |
| Bootstrap | Lệnh CLI **explicit**, chỉ tạo khi chưa có bất kỳ `users.account_type = 'Admin'`. Không seed mặc định, không chạy trong API/Worker startup/migration, không mở HTTP endpoint tạo Admin. |
| Số lượng | Tối đa một Admin toàn hệ thống, kể cả khi tài khoản đang `Suspended`. Bootstrap lặp là no-op; không thay password, contact, trạng thái hoặc session. |
| Tài khoản | `AccountType.Admin`, `UserStatus.Active`, đúng một email/phone đã chuẩn hóa, trường `EmailVerifiedAt` hoặc `PhoneVerifiedAt` được gán thời điểm bootstrap. Không gửi OTP; người vận hành chịu trách nhiệm xác nhận quyền kiểm soát contact trước khi nhập. Contact đụng bất kỳ user hiện có thì từ chối, không nâng cấp user cũ. |
| Bí mật | Password đầu vào từ terminal ẩn ký tự hoặc stdin đáng tin cậy; không dùng argv, URL, config trong repo, log, audit. Dùng `IPasswordHasher<User>`/policy F01.1; DB chỉ giữ hash. Cấu hình DB và JWT dùng cơ chế secret hiện có, không có giá trị mặc định mới. |
| Login | `POST /api/v1/admin-auth/login` riêng; chỉ `ADMIN/ACTIVE` thành công. `POST /api/v1/auth/login` vẫn chỉ nhận customer và operator. Admin dùng cùng JWT/refresh family đã harden ở F01.2. |
| Session | `auth/refresh` và `auth/logout` dùng chung cho Admin. Refresh và kiểm tra bearer đọc loại/trạng thái user cùng family **hiện hành trong DB**; claim cũ không cấp quyền. Access 10 phút, refresh 30 ngày, rotation/reuse/family isolation như F01.2. |
| Quản trị credential | CLI nội bộ có `rotate`, `suspend`, `activate`, `revoke-sessions`; không có recovery/reset public. `rotate` thay password hash và revoke **mọi** family; `suspend` chuyển trạng thái và revoke mọi family; `activate` chỉ khôi phục `ACTIVE`, không khôi phục session. `revoke-sessions` chỉ thu hồi family, không xóa/suspend Admin. |
| Cổng web | Admin web có login, trạng thái loading/validation/error, trang đã đăng nhập chỉ thông báo chưa có module quản trị, logout. Token ở React memory; reload phải đăng nhập lại. Customer/partner web không nhận/giữ phiên ADMIN. |

Tài liệu nghiệp vụ chỉ nêu `ADMIN` được seed hoặc tạo nội bộ, chưa định chính sách bootstrap/recovery. Quyết định cho F01.4 là **một Admin tối đa và recovery qua CLI có quyền DB**; đây là giới hạn của MVP, không phải quy trình cấp quyền cho nhiều quản trị viên sau này. Không dùng `users.status = PENDING_VERIFICATION/PENDING_ONBOARDING` cho Admin. Không xóa Admin để tạo lại hoặc chiếm contact của customer/operator. Đổi contact Admin, MFA và self-service password reset nằm ngoài F01.4.

## Threat model và quyền

| Nguy cơ | Biện pháp bắt buộc |
|---|---|
| Public/client tự cấp Admin | Không route register Admin. DTO allowlist chặn `accountType`, `status`, `role`, `permissions`, `isAdmin`, `userId` và field lạ. Service tạo Admin chỉ được CLI gọi; API không dựa vào giá trị client gửi. |
| Bootstrap đồng thời/lặp | Migration tạo partial unique index trên Admin; thao tác transactional. Một lệnh thắng, lệnh còn lại thấy Admin đã có/no-op hoặc báo conflict an toàn; không có hai Admin, không đổi Admin thắng. |
| Contact trùng | Unique normalized email/phone hiện có bảo vệ ở DB; từ chối cross-role thay vì biến user thành Admin. |
| Rò bí mật | Nhập password ẩn, không truyền bằng argv; không in password/hash/token/Authorization/full contact trong console, HTTP error, audit, log. Log lỗi cấu hình/DB chỉ là thông báo an toàn. Không lưu plaintext ở DB. |
| Dò tài khoản | Login sai password, sai contact, sai type hoặc suspended đều trả cùng `401 INVALID_CREDENTIALS`; giới hạn IP và contact như auth hiện có, `429 RATE_LIMITED` có `Retry-After`. |
| JWT cũ sau suspend/rotation/logout | Middleware/protected endpoint kiểm tra DB user và refresh family chưa revoke. `ADMIN/ACTIVE` là điều kiện ở mỗi request Admin. Refresh kiểm tra trạng thái DB; revoke tác động ngay cả khi JWT chưa hết hạn. |
| Token customer/operator vào Admin API | Endpoint Admin yêu cầu bearer hợp lệ, `ADMIN/ACTIVE` hiện hành trong DB và family active; không dùng claim `accountType` đơn lẻ. Quyền nghiệp vụ F02 sẽ thêm guard riêng. |
| Người giữ quyền vận hành CLI lạm dụng | CLI không triển khai qua HTTP/web; quyền chạy và DB credential phải do vận hành kiểm soát. Mọi thay đổi thành công ghi audit không chứa bí mật. |

## Dữ liệu, migration và giao dịch

- Tái sử dụng `users`, `refresh_sessions`, `audit_events`; không tạo bảng quyền/membership giả cho Admin. Giữ enum lưu dạng chuỗi hiện có (`Admin`, `Active`, `Suspended` trong DB; API trả `ADMIN`, `ACTIVE`, `SUSPENDED`).
- Migration tăng dần tạo unique partial index bảo vệ **mọi** hàng Admin: ví dụ `CREATE UNIQUE INDEX ux_users_single_admin ON users ((1)) WHERE account_type = 'Admin'`. Thêm check constraint riêng để Admin phải có verified timestamp tương ứng với normalized contact và chỉ mang `Active`/`Suspended` nếu không ảnh hưởng user cũ. Không sửa migration F01 đã áp dụng. Nếu DB nâng cấp đã có nhiều Admin trái invariant, migration phải thất bại rõ ràng, không tự xóa/chọn một user.
- Bootstrap validate đầy đủ contact, password policy và cấu hình cần thiết **trước ghi**. Transaction tạo user và audit `admin.bootstrap_succeeded` cùng commit. Unique constraint xử lý race ở DB; một transaction thua không ghi user/audit thành công. Bootstrap lặp không thay user. Có thể audit `admin.bootstrap_skipped` không chứa PII nếu cần truy vết; không sửa credential/trạng thái.
- CLI `rotate`/`suspend`/`activate`/`revoke-sessions` khóa Admin/transaction; cập nhật user, revoke tất cả `refresh_sessions` thuộc Admin khi quy định, và thêm audit trong cùng transaction. `rotate` so sánh policy password như registration, hash mới và cập nhật `updated_at`. Nếu fail, rollback toàn bộ. `activate` không tạo session. Chỉ có một Admin; thao tác khi chưa bootstrap hoặc trạng thái không hợp lệ phải từ chối an toàn, không tạo user tự động.
- Audit tối thiểu: `admin.bootstrap_succeeded`, `admin.bootstrap_skipped` (nếu ghi), `admin.password_rotated`, `admin.suspended`, `admin.activated`, `admin.sessions_revoked`, `admin.login_succeeded`, `admin.login_failed`; refresh/logout dùng action F01.2. CLI không xác thực danh tính người gõ nên `actor_user_id` để null cho thao tác hệ thống, tránh gán nhầm Admin làm người vận hành; `entity_id` trỏ Admin. Login thành công có actor Admin. Correlation id/UTC time và metadata không chứa contact/password/hash/token.

## CLI vận hành

Một entrypoint nội bộ, ví dụ `ShuttleBook.AdminCli`, hỗ trợ `bootstrap`, `rotate`, `suspend`, `activate`, `revoke-sessions` và exit code 0 khi thành công/no-op hợp lệ, khác 0 khi lỗi. CLI cần DB đã migrate; không tự tạo schema. Lệnh có thể nhận **tên thao tác** qua argv, còn contact/password qua prompt hoặc stdin riêng. Password phải được nhập ẩn nếu terminal tương tác, không echo vào console. Nếu stdin bị redirect, chỉ đọc secret từ luồng an toàn do người vận hành cấp; không hướng dẫn `echo <secret> | ...` vì shell history/process list có thể lộ. Không đưa password trong `.env` hoặc `appsettings`.

Thông báo CLI ngắn và không lộ secret: `Admin created`, `Admin already exists`, `Admin updated`, hoặc mã lỗi an toàn. Không in full contact, stack trace có tham số, connection string, SQL hay password. Tài liệu setup cần hướng dẫn thao tác PowerShell tại repo root sau khi CLI tồn tại, chỉ ghi lệnh gọi không chứa secret. Recovery khi quên password: người vận hành đã được cấp quyền DB chạy `rotate` bằng credential mới, thu hồi tất cả phiên. Khi nghi ngờ lộ phiên: `revoke-sessions`; khi phải khóa tài khoản: `suspend`. Một Admin duy nhất đồng nghĩa mất quyền vận hành CLI/DB sẽ không có kênh recovery trong ứng dụng; quy trình cấp quyền hạ tầng nằm ngoài F01.4.

## API và error contract

Base `/api/v1`, JSON camelCase, success bọc `{data, traceId}`; lỗi `application/problem+json` có `status`, `code`, `traceId`, không nêu tài khoản tồn tại/trạng thái. `Cache-Control: no-store` cho response chứa token/user. Body chỉ nhận field allowlist và giới hạn kích thước như F01.2.

| Method/path | Input | Thành công | Quyền/điều kiện |
|---|---|---|---|
| `POST /admin-auth/login` | `{contactType, contact, password}` | `200`, cấu trúc `AuthTokens` F01.2; `user.accountType=ADMIN`, `status=ACTIVE` | Public nhưng rate limited; chỉ Admin active, contact/password đúng. Không nhận role/status. |
| `GET /admin-auth/me` | Bearer | `200 {data:{userId,accountType:"ADMIN",status:"ACTIVE"},traceId}` | DB user `ADMIN/ACTIVE` và family active. Không trả contact. |
| `POST /auth/refresh` | `{refreshToken}` | `200` token mới như F01.2 | Admin active được phép; token cũ consumed, reuse revoke family. |
| `POST /auth/logout` | Bearer và `{refreshToken}` | `204` | Bearer, user và family khớp; revoke family. |

`/auth/login` phải tiếp tục từ chối Admin bằng `401 INVALID_CREDENTIALS`. Contact type/contact sai định dạng hoặc password rỗng/quá dài trả `400 VALIDATION_FAILED`; contact đúng định dạng nhưng không tồn tại, account không phải Admin, Admin bị suspend hoặc password sai đều trả `401 INVALID_CREDENTIALS`. `/auth/me` chung có thể trả type của bearer; mọi endpoint `/admin/*` khi được tạo sau này vẫn cần Admin guard riêng. F01.4 không tạo endpoint `/admin/*` nghiệp vụ chỉ để kiểm tra quyền.

| HTTP/code | Khi nào |
|---|---|
| `400 VALIDATION_FAILED` | JSON sai/thiếu field, contact/password sai định dạng hoặc độ dài. |
| `400 UNSUPPORTED_FIELD` | Client gửi field ngoài allowlist, gồm trường gán quyền. |
| `401 INVALID_CREDENTIALS` | Admin login sai contact/password, sai type/status; response giống nhau. |
| `401 INVALID_REFRESH_TOKEN` | Refresh/logout với refresh không hợp lệ. |
| `401 UNAUTHORIZED` | `me`/logout thiếu, sai, hết hạn bearer hoặc family đã revoke. |
| `403 FORBIDDEN` | Bearer hợp lệ nhưng không phải `ADMIN/ACTIVE` khi gọi Admin resource. |
| `429 RATE_LIMITED` | Vượt giới hạn; có `Retry-After`. |
| `500 INTERNAL_ERROR` | Lỗi nội bộ; không chứa secret/PII. |

Với `/admin-auth/me`, customer/operator bearer hợp lệ trả `403 FORBIDDEN`; Admin đã suspend hoặc session bị revoke trả `401 UNAUTHORIZED` vì bearer không còn hợp lệ theo middleware. JWT sai chữ ký/issuer/audience/hết hạn cũng `401`. Không tạo session khi login thất bại.

## UI admin-web

- Trang ban đầu là form đăng nhập contact type, contact, password. Client validate tối thiểu, không tự quyết định quyền; loading chống submit lặp. `401` hiển thị lỗi chung; `429` hiển thị thời gian chờ theo `Retry-After`; lỗi mạng/server rõ nhưng không lộ chi tiết nội bộ.
- Chỉ sau khi `admin-auth/login` trả `ADMIN/ACTIVE` và `admin-auth/me` xác nhận, hiển thị khu vực đăng nhập. Nếu response/`me` sai type hoặc không hợp lệ, xóa token trong memory và quay về login. Không tạo UI duyệt venue hoặc chức năng F02 giả.
- Trang sau login chỉ hiển thị thông báo **Chưa có module quản trị** và nút đăng xuất. Logout gọi API, xóa token memory cả khi request thất bại; F5/đóng tab mất phiên. Không ghi token/password vào URL, browser storage, console hoặc error telemetry.
- Customer/partner portal phải từ chối/clear phiên nếu response auth bất ngờ có `accountType=ADMIN`, không chuyển sang trang khách/chủ sân.

## Acceptance criteria

1. CLI bootstrap trên PostgreSQL đã migrate tạo đúng một `ADMIN/ACTIVE`, contact verified, password chỉ ở dạng hash, audit an toàn; không có route/API public tạo Admin hay credential mặc định.
2. Thiếu/sai secret, contact hoặc cấu hình thì fail safe, không tạo/thay user; contact customer/operator/Admin không bị nâng quyền. DB unique index bảo vệ bootstrap lặp/đồng thời và thao tác ghi trực tiếp.
3. CLI rotate/suspend/activate/revoke-sessions hoạt động atomic, audit/redact; rotate/suspend/revoke vô hiệu tất cả access và refresh session cũ; activate không phục hồi session.
4. Admin chỉ login qua `/admin-auth/login`; các trường hợp sai cho lỗi generic. Admin refresh rotation/reuse/logout theo F01.2; JWT invalid và account type/status/session cũ bị backend chặn dựa trên DB.
5. Customer/operator không truy cập `/admin-auth/me` và các Admin endpoint tương lai bằng cách thay claim/input. Customer/partner registration và login không tạo/cấp Admin; regression F01.1–F01.3 đạt.
6. Admin web chạy browser thật: login, lỗi/loading/rate limit, trạng thái chưa có module, logout/reload; memory-only token và không hiển thị chức năng F02 như đã hoạt động.
7. Migration fresh, repeat và upgrade từ DB có dữ liệu F01 qua PostgreSQL/PostGIS thật; test cạnh tranh, transaction, session và redaction có bằng chứng runtime. Chỉ đánh dấu DONE sau khi các testcase bắt buộc đạt và review độc lập không còn lỗi nghiêm trọng.

Nghiệm thu API/DB/browser live và review độc lập đã đạt ngày 2026-10-02; script live đã được sửa để chỉ dùng và dọn database test local có tên được xác minh. Sự cố mất dữ liệu database development trước khi sửa script được ghi tại `docs/progress.md`.
