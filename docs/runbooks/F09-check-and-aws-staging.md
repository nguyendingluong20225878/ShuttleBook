## B. Kiểm S3 thật trên bucket thử, trước production

S3 chỉ thay kho file `.media-local` cho ảnh cơ sở, QR và chứng từ thanh toán. Booking, payment, allocation, quote và outbox vẫn ở PostgreSQL/PostGIS. Mã S3 đã có trong API nhưng provider thật vẫn **NOT RUN**. Bucket thử dùng **dữ liệu giả**, không copy media local hoặc backup chứa dữ liệu thật lên AWS.

1. Trong AWS Console, chọn **một Region** và ghi lại mã Region. Tạo S3 bucket riêng cho staging, tên duy nhất và dễ nhận diện. Giữ **Block all public access = On**, **Object Ownership = Bucket owner enforced (ACL disabled)** và mã hóa mặc định. Không dùng S3 static website hosting cho bucket media private. Bật versioning nếu cần khôi phục object bị ghi/xóa nhầm, sau khi đã tính chi phí lưu nhiều phiên bản. Xem [AWS S3 public access](https://docs.aws.amazon.com/AmazonS3/latest/userguide/granting-public-access.html), [Object Ownership](https://docs.aws.amazon.com/AmazonS3/latest/userguide/about-object-ownership.html), [default encryption](https://docs.aws.amazon.com/AmazonS3/latest/userguide/default-bucket-encryption.html).
2. Tạo quyền thử **chỉ cho bucket này**: `s3:PutObject` và `s3:GetObject` trên `arn:aws:s3:::<bucket-thu>/venues/*` và `arn:aws:s3:::<bucket-thu>/payment-proofs/*`. API dùng `GetObject` để HEAD/đọc và phát signed GET. Tránh `s3:*`, bucket public hoặc access key cứng trong repo. Khi chạy trên EC2, gắn quyền vào **IAM role/instance profile**; trên PC thử, dùng quyền tạm từ IAM Identity Center/profile nếu có. [AWS EC2 IAM role](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/iam-roles-for-amazon-ec2.html), [AWS SDK .NET credential order](https://docs.aws.amazon.com/sdk-for-net/v3/developer-guide/creds-assign.html).
3. Trong S3 → bucket → **Permissions → CORS**, cho `PUT` từ `http://localhost:5174` (Partner) và `http://localhost:5173` (Customer); cho `GET` từ các origin cần signed GET. Allowed headers phải gồm `Content-Type`, `x-amz-checksum-sha256`, `If-None-Match`; khi có tên miền staging, thay bằng origin HTTPS đúng cổng. Không dùng wildcard origin. CORS chỉ cho phép browser gửi request; **không** biến object thành public. [AWS S3 CORS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/ManageCorsUsing.html).
4. Trên PC, cài AWS CLI v2 nếu chưa có. Nếu tài khoản có IAM Identity Center: `aws configure sso`, `aws sso login --profile <profile-thu>`, rồi `aws sts get-caller-identity --profile <profile-thu>` để xác nhận đúng account; **không gửi kết quả account/credential lên chat**. Tạo **database local thử riêng** có PostGIS, xác nhận tên DB trước migration, không trỏ S3 mode vào DB `shuttlebook` đang dùng và không chạy script live/drop trên DB này. Trong terminal **API** PowerShell, đặt `$env:AWS_PROFILE='<profile-thu>'`, `$env:Media__Mode='S3'`, `$env:Media__S3Region='<region>'`, `$env:Media__S3Bucket='<bucket-thu>'`, `$env:ConnectionStrings__ShuttleBook='<connection-string-DB-thu>'`. Xác nhận connection string trỏ đúng DB thử, chạy `npm.cmd run db:migrate` hai lần, rồi `npm.cmd run dev:api`. Các biến chỉ áp dụng tiến trình/terminal đó. Đặt API về Local bằng terminal mới hoặc xóa các biến tiến trình sau buổi thử. Nếu SDK báo không tìm credentials/profile, kiểm [AWS CLI SSO](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sso.html) và SDK .NET; không đưa access key/connection string vào `.env` hoặc chat.
5. Trong terminal **Worker** đặt cùng `ConnectionStrings__ShuttleBook` trỏ DB thử trước `npm.cmd run dev:worker`; chạy ba cổng web theo [checklist UI](../testing/F09-ui-manual-checklist.md). Partner tạo venue thử rồi upload ảnh và QR giả; Customer tạo booking thử, upload chứng từ ảnh giả. Mỗi lần: browser nhận presigned PUT 5 phút → upload → `complete` thành `READY` → đúng người xem lại. Xem bucket có object dưới đúng prefix, content type/size/checksum đúng; thử file sai checksum hoặc sai loại ảnh phải bị chặn. Ảnh venue đã publish chỉ hiển thị qua endpoint public hợp lệ; QR/chứng từ không lộ qua route ảnh công khai. Người ngoài quyền nhận 403/404 theo contract. URL S3 trực tiếp **không ký** phải bị chặn; signed URL hết hạn phải hết tác dụng. Presigned URL là quyền tạm của người ký, giữ kín như credential ngắn hạn. [AWS presigned URL](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html).
6. Thử lỗi mạng/quyền bằng **fixture giả**: tắt quyền bucket của profile thử hoặc ngắt mạng trong buổi thử, rồi xem API báo `MEDIA_UNAVAILABLE`/upload không `READY`; khôi phục quyền và thử lại. Không thay quyền của tài khoản production. Ghi kết quả từng case và số object thử; dọn **đúng prefix/object thử** sau khi đối chiếu, không xóa cả bucket dùng chung.

Lưu ý triển khai: bật S3 **không tự di chuyển** file `.media-local` cũ. Metadata `object_key` và bytes phải được đối chiếu/migrate theo kế hoạch riêng trước khi đổi môi trường có dữ liệu. Backup PostgreSQL/PostGIS vẫn độc lập với versioning/backup của S3.

## C. Chuẩn bị staging giống production sau khi S3 thử đạt

Chưa có artifact/service/reverse proxy EC2 và chưa có gate HTTPS thật trong repo. Vì vậy các bước sau là **thứ tự triển khai**, không phải lệnh đã chạy hay tuyên bố sẵn sàng production.

1. **Chốt thông tin trước khi tạo tài nguyên tính phí:** Region, tên miền staging và 4 origin (`customer`, `partner`, `admin`, `api`), ngân sách AWS/tháng, thời gian duy trì staging, số người dùng thử, chọn database. Dùng [AWS Pricing Calculator](https://calculator.aws/) tính EC2 + EBS + public IPv4 + data transfer + S3 + RDS/ALB/CloudFront nếu chọn; tạo [AWS Budget cảnh báo](https://docs.aws.amazon.com/cost-management/latest/userguide/create-cost-budget.html). Budget là cảnh báo chi phí, không đảm bảo chặn phát sinh ngay.
2. **Database đã chọn: cùng EC2.** Dùng PostgreSQL/PostGIS đúng major/extension tương thích với CI, đặt PGDATA trên **EBS mã hóa riêng** gắn vào EC2; kiểm mount tự động sau reboot bằng UUID và quyền filesystem. Nếu dùng Docker, khai báo volume Postgres trỏ tới EBS đã mount, healthcheck và restart policy; `compose.yaml` hiện tại chỉ phục vụ local, không dùng nguyên bản cho production. Chỉ bind PostgreSQL vào loopback hoặc Unix socket; security group **không mở 5432**. Cùng một EC2 là điểm lỗi đơn: phải có backup ngoài máy và restore drill. Không format một EBS volume đã có dữ liệu. [AWS EBS mount](https://docs.aws.amazon.com/ebs/latest/userguide/ebs-using-volumes.html).
3. **Tạo EC2 staging:** chọn image Linux hỗ trợ .NET/Node đã khóa phiên bản trong repo, dung lượng RAM/CPU/EBS theo ước tính tải, cùng Region với bucket; gắn IAM role chỉ có quyền S3 media cần thiết, quyền ghi backup riêng và Session Manager nếu dùng. Security group nhận 443 từ browser; 80 chỉ để redirect nếu cần. Dùng Session Manager để quản trị hoặc giới hạn SSH 22 theo IP của bạn. API 5080 và Postgres 5432 chỉ nội bộ. AWS tính tiền cả địa chỉ IPv4 công khai; kiểm dự toán. [EC2 IAM role](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/iam-roles-for-amazon-ec2.html), [Session Manager](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager-getting-started-instance-profile.html), [public IPv4](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/using-instance-addressing.html).
4. **Đóng gói ứng dụng:** build ba Vite app với `VITE_API_BASE_URL=https://api.<domain-thu>` và key MapTiler đúng môi trường; không dùng `ci-fixture-key`. `dotnet publish` API và Worker Release, tạo hai service/process riêng có restart; chạy migrator trên **DB staging đã backup** rồi chạy lần hai để kiểm lặp. Static web có thể phục vụ qua web server trên EC2 hoặc S3 static bucket riêng + CloudFront; **không dùng bucket media private làm public website**. Repo hiện chưa có manifest triển khai tự động cho EC2 nên cần viết và thử phần này trước khi thực hiện.
5. **HTTPS và phiên:** trỏ DNS 4 origin vào web/API, cấp TLS certificate; nếu dùng ALB, HTTPS listener cần certificate và có thể dùng ACM. Điền `Cors__AllowedOrigins__0...`, `BrowserSession__CustomerOrigin`, `BrowserSession__PartnerOrigin`, `AdminSession__AllowedOrigin` bằng origin HTTPS chính xác; secret DB/JWT/OTP lưu ngoài Git. API hiện **chưa cấu hình trusted forwarded headers**; cookie Admin đặt `Secure` theo `Request.IsHttps`, nên phải sửa/kiểm tra nhận diện HTTPS sau reverse proxy trước khi public. Kiểm login → F5/restore/logout của cả ba cổng qua HTTPS và xem cookie `HttpOnly`, `Secure`, `SameSite` đúng. [AWS ALB HTTPS](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/create-https-listener.html).
6. **Giám sát và phục hồi:** health `/health/live`, `/health/ready` chỉ chứng minh API; cần giám sát riêng Worker/outbox/booking chờ owner >30 phút, dung lượng EBS và log không lộ PII, alarm có người nhận. Tạo lịch `pg_dump` của DB và giữ bản **ngoài EC2** trong bucket backup private riêng (không chung prefix media), mã hóa/giới hạn IAM; thêm EBS snapshot theo lịch nếu phù hợp. Snapshot không thay phép thử restore logic. Chốt retention, RPO/RTO; diễn tập restore vào EC2/DB và prefix **khác**, kiểm QR/proof đúng scope. Không chạy script backup local hiện tại như lịch backup EC2 khi chưa thiết kế lại vận hành. Giữ bản build trước release để rollback ứng dụng; không tự downgrade schema. [AWS EBS snapshots](https://docs.aws.amazon.com/ebs/latest/userguide/ebs-snapshots.html).
7. **Gate trước người dùng thật:** S3 provider thật PASS, CI SHA ứng viên PASS, U04 manual PASS, staging HTTPS + cookie + CORS PASS, test concurrent booking/quote PostGIS PASS, backup/restore và alert PASS, pilot dữ liệu giả đạt. Chỉ sau đó mới cân nhắc cutover production theo quyết định riêng.

## E. Việc cần chốt khi chưa có domain/ngân sách

1. **Ngân sách:** đặt mức chi tối đa **mỗi tháng** bằng VND hoặc USD và thời gian vận hành ước tính. Trước khi mua, lập estimate theo Region cho EC2, EBS, IPv4, data transfer, S3, database, TLS/load balancer/CDN, email/SMS và giám sát. Bật AWS Budget với địa chỉ nhận cảnh báo; cảnh báo có thể đến trễ so với phát sinh phí, nên người vận hành còn phải xem Billing định kỳ. [AWS Budgets](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html).
   - Ảnh AWS Console chỉ xác nhận đăng nhập; vùng chọn trong ảnh là **Europe (Stockholm)**, không chứng minh đã có tài nguyên hay đây là Region sẽ dùng. Vào **Billing and Cost Management → Cost and Usage / Free Tier / Credits** để xem account plan Free/Paid, credit còn lại, hạn Free plan và usage. AWS nói Free plan chấm dứt sau 6 tháng hoặc khi hết credits (điều kiện đến trước), sau đó tài khoản đóng nếu không nâng cấp; vì vậy production có người dùng thật cần kế hoạch Paid plan và ngân sách vận hành, không dựa vào Free plan như hạ tầng lâu dài. [AWS account plans](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html), [theo dõi Free Tier](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/tracking-free-tier-usage.html).
   - Trong **IAM → Security credentials** của tài khoản root, xác nhận MFA đã bật; ưu tiên passkey/security key nếu có. Dùng danh tính quản trị riêng cho thao tác thường ngày và IAM role cho EC2. Không gửi ảnh có account ID đầy đủ, access key, recovery code hoặc token. [AWS root MFA](https://docs.aws.amazon.com/IAM/latest/UserGuide/enable-mfa-for-root.html), [IAM best practices](https://docs.aws.amazon.com/IAM/latest/UserGuide/root-user-best-practices.html).
2. **Tên miền:** chọn tên có thể đăng ký tại Route 53 hoặc nhà đăng ký khác; dự kiến `customer.<domain>`, `partner.<domain>`, `admin.<domain>`, `api.<domain>` để cấu hình origin và HTTPS đồng nhất. Domain có phí đăng ký gia hạn; DNS có thể quản lý ở Route 53 dù mua domain nơi khác. Chỉ điền domain **đã sở hữu** vào certificate/DNS thực tế. [AWS Route 53 domain](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/dns-configuring-new-domain.html).
3. **Kênh OTP:** người dùng chưa chốt việc giữ đăng ký bằng số điện thoại khi mở thật. Nếu giữ, cần SMS provider thật và test nhận OTP; nếu chỉ email lúc đầu, phải chỉnh UI/API để ẩn hoặc từ chối phone registration và kiểm lại. Không dùng luồng email giả `@phone.shuttlebook.test` trên production. Với database cùng EC2 đã chọn, chốt RPO/RTO, retention và người nhận cảnh báo trước khi thiết kế backup vận hành.
4. **Mốc cấp quyền:** sau khi có estimate và kiến trúc để xem lại, người dùng duyệt riêng việc tạo tài nguyên tính phí, chuyển dữ liệu và đưa người dùng thật vào. Trước đó có thể hoàn thiện code, test và tài liệu trong local mà không phát sinh AWS.

Khi cần hỗ trợ lỗi, gửi: gate + commit SHA, lệnh/bước Console, mã HTTP hoặc tên exception, thời điểm, ảnh đã che dữ liệu và kết quả mong đợi. Không gửi AWS access key, session token, presigned URL, OTP, QR thật hoặc connection string.
